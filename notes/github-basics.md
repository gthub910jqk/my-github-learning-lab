# GitHub 基础概念

## Repository

Repository 是仓库，用来保存一个项目的文件、说明和修改历史。

## README

README 是项目说明文件，别人打开仓库后通常最先看到它。

## Commit

Commit 是一次有说明的修改记录。

## Issue

Issue 是任务、问题或改进建议，可以用来管理项目中的待办事项。

## Branch

Branch 是分支，可以在不影响主线的情况下独立修改内容。

## Pull Request

Pull Request 是提交修改并请求合并的流程，可以用来检查、讨论和合并修改。

## Add My Notes
GitHub 是什么： 
```
- 是云端的一个代码仓库平台， 每个人有自己代码仓库
- 支持多人合作开发，以及版本控制，在不同的分支做开发，合并，提交
- 开源与社交属性， 浏览其他人发布的项目，
```
  
Repository 是什么： 
``` - 是一个代码仓库，包括了一个项目所有开发文件的 总目录， 
- 并且包括了历史变更，追踪做了哪些版本的变更
- 包括有哪些内容：文件，代码， readme.md， isssue 问题处理
- 仓库类型
	- 公共：public，开源项目仓库， 任何人都可以可以看到
	- 私有：private，个人或者团队的项目， 指定人可以看到
```
Commit 是什么： 
```
- 在仓库当中，提交一个代码版本，在仓库中保存一个存档的“版本”
- 包括了，谁，在什么时间， 改了什么内容， 以及提交信息
- 能够看到每一次提交历史信息， 可供回退，恢复，审计等，
```
Issue 是什么： 
```
- 仓库（repo）的任务白板， 主要记录问题bug，新功能， 新手求助，任务分配等
- 生命周期：
	- open， 开启状态， 正在解决
	- close，已解决
```
Pull Request 是什么：
```
- 合并申请，把自己修改的部分，合并到项目的申请， 需要review之后才能合并
- 为什么要pull request
	- 避免协作项目发生代码到混乱， 引入PR机制。
	- 项目仓库-fork 到自己的仓库-clone到本地修改-提交自己的仓库-PR（review）-合并
```

Merge 是合并，把一个分支或 Pull Request 里的修改合并到目标分支。

## GitHub Pages

GitHub Pages 可以把仓库中的静态网页发布成公开网站。
